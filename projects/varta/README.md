# Варта

Агент спостереження за страйкбольною базою: локальне відео, журнал подій,
панель оператора та необов’язкові хмарні описи. Самостійний проєкт у
`projects/varta/`; не інтегрований із системою керування транспортом цього
репозиторію. Не керує приводами або стрільбою.

## Архітектура

```text
IP-камери Hikvision → LAN / мости HaLow → базовий ПК
                                          ├─ FFmpeg: RTSP, запис MKV, кадри
                                          ├─ Python/FastAPI: події та API
                                          ├─ SQLite: журнал і черга аналізу
                                          ├─ OpenAI API: вибрані кадри й журнал
                                          └─ React/Vite: браузер оператора
```

Базовий ПК працює постійно; окремому комп’ютеру оператора потрібен лише
браузер. Закриття панелі не припиняє запис. Передбачено до трьох камер;
офісний профіль містить дві: одну через LAN і другу через радіоміст.

## Реалізовано

- RTSP-приймання, повторне підключення, запис оригінального відео без аудіо.
- Детектор змін у заданій зоні, темного кадру та втрати/відновлення зв’язку.
- SQLite-журнал, кадри подій, фільтри, позначка перегляду, завантаження архіву.
- Панель трьох камер, чат, пауза аналізу та пароль доступу оператора по LAN.
- Необов’язкові описи через Responses API; черга, повтори та погодинний ліміт.
- Деморежим без зовнішніх API-запитів; без ШІ чат повертає локальну вибірку.
- Офісний профіль та RTSP-діагностика через TCP/UDP без виведення секретів.

## Запуск на Windows

Потрібен Python 3.12, 64-bit. Команди виконувати з `projects/varta/`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m backend
```

Відкрити http://127.0.0.1:8765. За замовчуванням працює демонстрація.
Готова панель у `dist/` уже включена, тому Node.js для такого запуску не потрібен.
Для перескладання панелі потрібні Node.js 20.19+ та npm:

```powershell
npm install
npm run build
```

Для офісного тесту скопіюйте шаблони, не перезаписуючи власні налаштування:

```powershell
Copy-Item config.office.json config.local.json
Copy-Item .env.example .env
```

Локально заповніть у `.env` адреси `VARTA_CAM1_RTSP`, `VARTA_CAM2_RTSP` та
`VARTA_OPERATOR_TOKEN` (мінімум 16 символів). Потім:

```powershell
.\.venv\Scripts\python.exe -m backend --lan
```

На комп’ютері оператора: `http://IP_БАЗОВОГО_ПК:8765`. Доступ призначений
для довіреної LAN; TCP 8765 дозволяється лише потрібній локальній мережі.
Для хмари додайте `OPENAI_API_KEY`, увімкніть `cloud_enabled` у
`config.local.json` і перезапустіть сервер. Ключі та паролі не зберігайте в Git.

## Перевірки й поточний стан

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m backend.diagnose
```

На момент перенесення 17.09.2026 набір містить 14 автоматичних тестів.
Попередня локальна перевірка пройшла, включно з реальним процесом FFmpeg
на синтетичному відео. Це не підтверджує роботу з фізичними Hikvision.
Діагностика зберігає звіт у `data/diagnostics.txt`.

## Відомі проблеми та обмеження

- Під час офісного тесту камера 1 не передала відео у «Варту», хоча користувач
  повідомив про наявність відео в іншому переглядачі. Точне джерело перегляду
  не уточнено. Причина ще не встановлена; очікується звіт діагностики.
- На отриманому скриншоті адреса камери 2 ще не була налаштована.
- Додано діагностику та уточнено RTSP-тайм-аут FFmpeg; це ще не підтверджене
  виправлення офісного підключення.
- Огляд у панелі — 640 px, 1 кадр/с; архів зберігає оригінальний потік.
- Детектор змін реагує також на тіні та рослинність; він не розпізнає людей.
- Реальний хмарний API, тривалий тест трьох камер і автономність 8 годин
  ще не перевірені. Автозапуск як служба ОС не налаштований.
