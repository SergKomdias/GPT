# Оновлення приймання відео й діагностики

1. На базовому ПК зупиніть сервер «Варти»: Ctrl+C.
2. Розпакуйте `varta-camera-update.zip` безпосередньо у папку «Варти» з
   погодженням заміни файлів у `backend`. Правильний шлях має вигляд
   `C:\Varta\backend\diagnose.py`, а не додаткової вкладеної папки.
   У ZIP немає .env, config.local.json або записів, тому вони зберігаються.
3. З цієї папки в PowerShell запустіть:

```powershell
.\.venv\Scripts\python.exe -m backend.diagnose
```

Діагностика отримує один кадр кожної налаштованої камери, спочатку через TCP,
за невдачі — через UDP. На одну спробу відведено до 20 секунд.
Запис не ведеться, API не викликається. Логіни, паролі й адреси не виводяться.
Звіт зберігається в `data/diagnostics.txt`.

4. Надішліть текст звіту. `FRAME_OK` означає, що FFmpeg отримує кадр;
   `AUTH` — відмову авторизації; `TIMEOUT` — відсутність кадру до тайм-ауту;
   `OUTPUT` — проблему вихідного потоку або запису; `FFMPEG_OPTION` —
   несумісний параметр. `NO_FRAME` не встановлює конкретну причину.
5. Сервер знову запускається звичайною командою:

```powershell
.\.venv\Scripts\python.exe -m backend --lan
```

Оновлення використовує RTSP-параметр тайм-ауту, який надає комплектна збірка
FFmpeg, і показує безпечну категорію помилки в журналі подій.
Це не підтверджене виправлення вашої камери: конкретну причину встановлюємо
за діагностикою на базовому ПК.
