# Варта — агент спостереження за страйкбольною базою

Локальний сервер для міні-ПК і браузерна панель оператора на окремому ноутбуці.
Три Hikvision DS-2CD2D25G1/M-D/NF передають RTSP через три пари Heltec HT-HD01
та комутатор MikroTik. Мережеві параметри самих мостів програма не змінює.

Це перша робоча версія. Реальні камери й обліковий запис OpenAI ще не підключені.
За замовчуванням відкривається чітко позначений демонстраційний режим без
фальшивого відео та без зовнішніх API-запитів.

## Що реалізовано

- Приймання до трьох RTSP-потоків, повторне підключення після обриву.
- Запис оригінального відео без перекодування у хвилинні MKV-фрагменти.
  Аудіо не записується. Межа фрагмента залежить від ключових кадрів камери.
- Панель показує зменшений огляд 640 px із частотою 1 кадр/с, а не повношвидкісний
  прямий ефір. Це обмеження першої версії. Оригінальна частота зберігається в архіві.
- Локальне виявлення змін у прямокутній зоні, затримка повторних сповіщень,
  виявлення тривалого темного кадру, події втрати й відновлення відеозв’язку.
  Це простий детектор змін, а не розпізнавання людей. Вітер і тіні можуть викликати
  хибні спрацювання; темний кадр не доводить перекриття камери. Нативні події
  Hikvision ISAPI поки не використані.
- SQLite-журнал, кадр події, фільтри, позначка перегляду, завантаження відеоархіву.
- Хмарний опис кадрів через OpenAI Responses API, якщо його налаштовано.
  Для кожного виклику store=false; у хмару передаються кадри вибраних подій або
  текст вибірки журналу. Постійне відео у хмару не передається.
- Черга аналізу в SQLite, максимум три спроби, пауза між спробами, спільний
  погодинний ліміт для описів і чату, що зберігається після перезапуску.
  Запит, перерваний аварійним завершенням сервера, позначається помилкою без
  автоматичного дублювання платного виклику. Події, створені без налаштованої
  хмари, залишаються локальними й автоматично пізніше не відправляються.
- Без ШІ чат повертає чесно позначену локальну вибірку. Він не імітує мовну модель.
  Запити ШІ отримують до 100 останніх подій у вибраному інтервалі, не весь архів.
- Запис та аналіз на міні-ПК працюють незалежно від відкритої панелі ноутбука.

## Запуск на цьому комп’ютері

Залежності вже встановлені, панель зібрана. У PowerShell із цієї папки:

```powershell
.\Start-Varta.ps1
```

Відкрийте http://localhost:8765. Натисніть «Тестова подія», відкрийте її,
позначте як переглянуту, поставте агенту запитання. Зупинка сервера — Ctrl+C.
Якщо політика PowerShell блокує сценарії, можна запустити без сценарію:

```powershell
.\.venv\Scripts\python.exe -m backend
```

## Встановлення на міні-ПК

Python 3.12+, Node.js 20.19+ та npm. Папку проєкту копіювати без .venv,
node_modules і персональних даних; оточення створюється заново на новому ПК.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
npm install
npm run build
Copy-Item config.example.json config.local.json
Copy-Item .env.example .env
```

Відредагуйте `.env` локально у текстовому редакторі:

- `VARTA_CAM1_RTSP`, `VARTA_CAM2_RTSP`, `VARTA_CAM3_RTSP` — адреси камер із
  обліковим записом, якому дозволений перегляд відео.
- `OPENAI_API_KEY` — ключ API, якщо потрібен хмарний аналіз. Оплата API окрема
  від підписки на чат. Не вставляйте ключ у браузер чи повідомлення.
- `VARTA_OPERATOR_TOKEN` — довгий пароль для входу з ноутбука (мінімум 16 символів).

У `config.local.json` змініть `demo` на `false`; `cloud_enabled` на `true` лише
після введення ключа. Модель `gpt-4.1-mini` можна змінити на доступну у вашому
API-проєкті модель із підтримкою зображень і Responses API. Наявність ключа
не означає, що підключення перевірене: реальний результат з’явиться після запиту.

Для доступу з ноутбука:

```powershell
.\Start-Varta.ps1 -Lan
```

На ноутбуці відкрийте `http://IP_МІНІ_ПК:8765` та введіть пароль оператора.
Без пароля API відмовляє віддаленим клієнтам. Доступ через HTTP призначений
для довіреної локальної мережі. Для доступу через недовірену мережу потрібен
VPN або HTTPS. Не відкривайте цей порт безпосередньо в інтернет.
Правило брандмауера має дозволяти доступ лише потрібній локальній мережі.

## Зони, запис і ліміти

- `roi`: `[ліва, верхня, права, нижня]` у частках ширини й висоти від 0 до 1.
  Наприклад `[0.2, 0.1, 0.8, 0.9]`. Зона задається для детектора, не обрізає архів.
- `motion_threshold`: частка змінених пікселів (0.06 = 6%); потрібні два
  послідовні спрацювання. Аналізується 2 кадри/с.
- `cooldown_seconds`: мінімальний інтервал між подіями руху з однієї камери.
- `cloud_calls_per_hour`: ліміт кількості запитів, не гарантований доларовий бюджет.
  Типове значення 30. Кожна спроба, включно з невдалою, використовує ліміт.
- `recording`, `retention_days`, `max_recording_gb`, `min_free_gb`: керування архівом.
  Зберігання за замовчуванням 7 днів/100 ГБ, резерв диска 5 ГБ.
  Старі закриті фрагменти автоматично видаляються; активні та останні 3 хвилини
  не видаляються. Тому ліміт розміру може тимчасово перевищуватися.
  За нестачі місця запис зупиняється, огляд залишається. Після звільнення місця
  запис поновлюється при наступній перевірці диска (до 30 секунд плюс перепідключення).
- «Призупинити аналіз подій» зупиняє детектор змін і чергу описів; відеозапис та
  події стану зв’язку продовжуються. Уже надісланий запит ШІ може завершитися.

Зміни конфігурації потребують перезапуску. У `data/` зберігаються SQLite,
кадри та відео; папка не віддається браузеру напряму. Секрети не входять у
публічний API. RTSP-паролі є в аргументах локального процесу FFmpeg, тому доступ
до облікового запису міні-ПК має бути обмежений. При жорсткому вимкненні живлення
останній активний фрагмент може бути пошкоджений; попередні закриті залишаються.

## Перевірки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
npm run build
```

Тести перевіряють збереження журналу й лімітів після перезапуску, авторизацію,
захист запитів від іншого сайту, відсутність секретів у статусі, зони й затримку
детектора, безпечне очищення архіву, формат запиту ШІ з підміненою відповіддю,
а також реальне приймання синтетичного відео через FFmpeg із записом та JPEG-кадрами.

Перед використанням у грі потрібно перевірити саме три фізичні Hikvision,
реальний API, тривале відключення/відновлення мережі, місткість диска та
8-годинну автономність комплекту. Автозапуск як служба ОС ще не налаштовано.

Документація API: https://developers.openai.com/api/docs/guides/images-vision
